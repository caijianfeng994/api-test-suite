## 接口测试 Skill 强制约定

所有接口相关任务必须且仅使用 `api-test-suite`。禁止使用 `api-contract-to-test-cases`、`api`、`refact-api-test`、`migration-api-test` 及仓库旧接口入口。

1. 先读 `api-test-suite` 主入口，再按场景插件与 `core/` 阶段执行。
2. `test_kind` 路由：`functional` | `refactor` | `migration`；语义不清时只询问 `test_kind`。
3. `run_mode`：
   - `contract`：契约/OpenAPI/Proto/契约 Issue → 可追溯用例；流程为 discovery → contract → planner → generator（文档）；不造数、不执行。
   - `full`：默认执行类；含契约分析（除非显式 `stages.contract=not_applicable`）+ ops + plan + gen + exec + report。
   - `plan` / `generate` / `execute`：分段运行；`refactor` 使用 `baseline` | `replay`。
4. 用户说「按契约写用例 / 条款矩阵 / 只设计不执行」时，使用 `run_mode=contract`（通常搭配 `test_kind=functional`）。
5. 产物目录：`exports/api-test-suite/<test_kind>/<slug>/<run_id>/`
6. 契约产物：`contract-clauses.json`、`contract-analysis.md`、`traceability-matrix.md`
7. 编写用例前必须：先探测 YApi 连通并拉取候选，再按服务名用 CodeWiki（`list_codewiki_repos` → 唯一匹配 Wiki 名 → `get_api_reference`）核对 GitLab 各 proto 的 HTTP path。YApi∩proto 与仅 proto 有的都生成用例；仅 proto 有的标明 `source_label=proto有`。会话未注册时执行 `python .claude/skills/api-test-suite/scripts/fetch_yapi_interface.py --ping --output "<run_dir>/yapi-ping.json"` 与 `python .claude/skills/api-test-suite/scripts/fetch_codewiki_interfaces.py --service-name "<name>" --output "<run_dir>/codewiki-raw.json"`，再执行 `python .claude/skills/api-test-suite/scripts/filter_yapi_by_proto.py --yapi "<run_dir>/yapi-raw.json" --proto "<run_dir>/codewiki-raw.json" --service-name "<name>" --output "<run_dir>/yapi-proto-filter.json"`。YApi 有而 proto 无该 path 的接口自动过滤、不维护 case。**实现层已标下线**（Handler/Service 注释如 `// 2025.4.1日下线` 或下线空壳，见 `reference/code-offline-filter.md`；**证据缺口必须走 path/同文件兄弟兜底**，并写 `code-offline-filter.json` 的 `scan.by_path`）→ `reason=code_offline`，同样不维护。禁止把仅 proto 有的接口假写成 YApi 文档。禁止调用 `list_gitnexus_repos` / `get_route_graph` / `get_symbol_context`（例外：下线扫描与缺参校准，均最小范围）。catalog 保留条目仍为 `source.type=gitnexus`。functional 单接口在 k8s 测试环境中，若 path 第一段是合法服务名，可按 `/good-order/good/list` → `http://good-order.7to12/` 推导 Base URL；最终 URL 必须保留完整 path。
8. 用户给了 YApi 链接但当前会话没有对应 MCP 工具时，必须执行 `python .claude/skills/api-test-suite/scripts/fetch_yapi_interface.py`（具体接口 `--url`；项目页 `--project-url` / `--project-id`；分类 `--cat-url` / `--cat-id`），禁止只因 Cursor MCP 面板未挂载而跳过。YApi `--ping` 失败则 discovery 停止。项目页/`projectId`/「某服务全部接口」**优先** `list_interfaces_by_project`；该工具失败才按 `core/yapi_search` 旁路逐分类 `list_interfaces_by_cat`。禁止用 `search_interface` 冒充全量。
9. 用例默认必须接近回归测试：YApi/proto/代码只用于读取字段、类型和值域，所有已声明的 Path/Query/Body 字段一律默认必填，不采信 required/optional 标记（见 `reference/regression-case-semantics.md`）。functional/auth 缺任一有效字段即不可执行并记录 `required_binding_missing`。**禁止**默认 smoke；**禁止**对无资源 ID 的列表/配置接口生成「资源不存在 → 4xx」。过滤 ID 的未知值按契约或实测空列表语义断言。functional 须满足闭环 6 条（fixture 追溯、HTTP+业务码+schema、verify_read、state_check/policy、test_marker+cleanup、independent）。**编辑接口先 GET 详情再 PUT/PATCH**（`reference/edit-get-then-put.md`），不得用稀疏示例 body 硬编辑。**结构化 4xx 且 JSON 含 code/errcode/message/errmsg/reason 算通过**，仅 5xx/UNKNOWN 失败。可用 `scripts/generate_full_cases.py` 展开；`scripts/validate_run.py` 会校验闭环字段。缺真实参数时按 `reference/fixture-fallback.md`：造数工具（含创建补数+独立种子）→ 查库 → 本套件 `web_cli/SKILL.md`。**禁止部分绑定收工**（只绑了 strategyId/userId 就标缺参）：schema 差集须补齐或 pending+三步 attempts；同表同行字段一次取全；`validate_run` 对无证据的 `required_binding_missing` 报 `fixture leak`。步骤名不算证据：禁止用 `no_dedicated_fixture_factory`、无字段 `SELECT` 的查库摘要、`shadow_path_lookup` 菜单文档检索凑三步；必须有创建接口扫描或实际调用、字段级 SQL，以及 `execution/web-cli/` 证据和 `opened_url`/`captured_api`。判别/条件字段与下游约束见 `reference/fixture-discriminator-fields.md`。省略必填 path 用 `omit_required_path`（path 去 `{param}`，禁止空串）。禁止编造连接串与占位 ID，禁止接口造数时改用仓库根目录 `web_cli`。**零日志不等于未调用 APP**：discovery 须按 `reference/app-usage.md` 写 `app-usage-evidence.json`；仅完整 `not_called_by_app` 可省略 auth，其余仍生成 auth。
9a. 数据库和 Shadow 都没有现有数据时，必须实际调用同资源创建 API、造数脚本、`web_cli/SKILL.md` 或后台创建页面。仅有 catalog 扫描、查询接口或「无专用造数脚本」不得进入 `required_binding_missing`；pending 必须记录造数目标与 `failed|blocked` 结果。
9a2. `PUT`/`PATCH`/`DELETE` 的资源主键按 `reference/fixture-fallback.md`：先同 path 创建接口造数，再用同 path 获取/列表接口取主键。两步都不满足才查库，来源必须是 `db:<service>.<table>.<column>`，并在 `resource_seed_attempts` 记录创建/获取的 `failed|blocked`。禁止把库抽样的其它列填进 `id`。
9b. YApi 与代码都有、但执行返回 HTTP 501 或 `not implemented` / `Unimplemented` 时，按 `reference/unimplemented-traffic.md` 查该 path 近 30 天线上访问日志。有调用保留 `failed`；0 调用把整条接口改为 `ignored`，不计入失败。查询失败不得当成无调用。证据写入 `execution/unimplemented-traffic.json`。
9c. catalog 每个保留 path 按 `reference/zero-traffic-ignore.md` 统计近 30 天调用数，不能只查缺绑定接口。`hit_count=0` 整条忽略，包括参数已绑定后仍返回 HTTP 500 的接口。有调用的 500 保留失败。证据写入 `execution/path-traffic.json`。
9c. 成功路径响应 schema 按 `reference/code-response-schema.md` 以 CodeWiki/proto 出参为准。根类型 `[]Xxx` 断言 array；字段名用代码原文；`repeated` 不得被 YApi `properties` 改判成 object。与 YApi 冲突时 `source=code_calibrated`。禁止无代码证据时默认 `type=object`。
9d. 接口返回失败后，按 `reference/code-failure-calibration.md` 用代码核对 HTTP 状态码和响应格式。两者都与代码实现一致时执行记 `passed` 并进入回归集；对不上才保留 `failed`。证据写入 `code-validation-evidence.json`。
9e. 夹具三步仍没有非空真值时，按 `reference/code-request-values.md` 读处理函数。代码字面量或无校验透传文案写入 `code:` 绑定；处理函数未读取的字段标 `usage=code_unused` 并省略。三种情况都不成立时，按 `reference/binding-log-supplement.md` 查该 path 近 30 天线上访问日志，用请求里的非空值回填，来源 `log:<path>#<位置>.<字段>`。日志确认字段未出现、path 无调用，或敏感字段不能抄明文，才 `required_binding_missing`。查询失败不得当成没有值。证据写入 `execution/binding-log-supplement.json`。禁止只因库或后台没有该列就跳过代码核对和日志补数。
10. 已生成 `test-cases.md` 后必须执行 `python .claude/skills/api-test-suite/scripts/upload_gitlab.py --run-dir "<run_dir>" --service-name "<服务名>"`（`core/gitlab-upload`），推到 `backsys-testgroup/mstrategysddtestcase` 的 **`api/<服务名>/`**。上传器必须在 clone 前先跑 `validate_run.py` 预检；完整库按 id 增量合并；回归集同 id 只接受 `regression_ready=true`、`execution_status=passed`、无 blocker 的 incoming（执行通过即晋升并保留请求取值，含代码核对一致的 5xx），失败/跳过/缺失不得覆盖或删除远程成功版本；fixture 合并必须保留远程回归引用。合并后 staging 再做一致性/敏感检查，通过后才 commit/push。上传完整/回归/backlog 文档、脱敏的 `code-validation-evidence.json`（若有）及独立工程 5 文件，README 写明 `npm ci && npx playwright test`。交付报告完整用例数、已晋升数、backlog 数、`protected_remote`、`promoted`；正常情况下已晋升数应等于 passed 数。禁止把“全部上传”表述成“含失败/跳过也可回归”。
11. 完成前必须执行 `python .claude/skills/api-test-suite/scripts/validate_run.py "<run_dir>"`，且 `run-context.json.status=completed`、`gitlab-upload.json.ok=true`；GitLab 工程必须可独立安装和收集。
